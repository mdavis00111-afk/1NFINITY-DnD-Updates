Source checkpoint, not release or runtime acceptance. Builds on B1/B2/B3 and preserves A2 MapView v1 at 959705e.

## Authority and lifecycle
B3 coordinator validates provider reply identity, frozen campaign/actor/turn/revision, complete structured envelope, evidence excerpt and known public references. It calls reconcile_current automatically on successful geography reply. geography_reconciler.gd commit_bundle(campaign_id, exact_local_bundle, known_ids, reviewed_prose=false) checks active snapshot and persisted B2 receipt, never interprets a provider approval. Existing receipt lookup detects completed narration; stale/replayed requests do not reroll or duplicate events. Ordinary supported descriptive facts do not require player confirmation. B2 local adjudication and explicitly unsupported mechanical actions remain exactly as before. The existing GUI composer stays disabled pending lead integration/QA.

Planning uses bound campaign-local read snapshots and generated SQL only, then one BEGIN IMMEDIATE bridge batch: exact turn guard, one narration event and turn_narrations row, accepted fact/discovery/alias/link/route/region/actor commands and one audit row per proposed fact, revision increment, pending receipt clear and guard deletion. Source event is assigned by that batch, not the AI. Failure rolls back all writes; retry looks up durable receipt, does not resolve mechanics again. Candidate text and conflicts remain local; no arbitrary provider SQL. Audit detail JSON retains original bounded proposal/evidence and reason, even when the sanitized accepted event excludes a contradicted claim. No network inside SQL transaction.

## Reconciliation
- Stable ID is primary. New proposal-local keys resolve only within packet, or to a unique scoped canonical name/visible alias (known offered context or explicit parent/region; unrelated global name alone not sufficient). Local name/alias collision searches include private records to avoid accidental duplicates but do not reveal private IDs/names. Ambiguous or hidden matches defer/conflict. Existing kind, established name, parent/region, coordinates, routes, population/occupancy and identity are never silently overwritten. Existing non-null canonical fields are preserved. New nested locations/regions depend on resolved parent references; unresolved/cyclic dependency graph is deferred. Existing parent/region corrections require later trusted reconciliation, not implicit reassignment.
- New named places/regions, public aliases, relative geography, roads/routes, reported/observed discovery, static descriptions and named local descriptive NPCs are supported. New absolute position/footprint/polyline coordinates are not accepted from B3; provisional positions are null. Distances must be explicitly stated in miles (numeric or supported number words); direction orientation checked against evidence. Existing relation/route disagreements, reversed relation direction and inconsistent established endpoint geometry/uncertainty are conflicts. No invented geometry or forced map origin. Route existence is not travel or clearance. No AI visited/surveyed, time, HP, inventory, dice, encounter, actor relocation, movement path or mechanical patch.
- Existing public descriptions can be filled only if empty using narrowly validated static appearance/material/sensory descriptions with exact evidence; established descriptions preserved. Other optional claims (population, elevation, terrain, occupancy, asset IDs and unverified prose) are deferred/audited rather than silently treated as canon. Asset selection remains renderer's stable category/variant fallback; no AI resource path or asset whitelist bypass. Descriptive identity may still be accepted when optional fields are deferred; only validated fields become canon. No new quest assignment or forced plot.
- Discovery is monotonic unknown→reported→observed→visited→surveyed. New mentioned entity is reported; explicit visible/in-sight evidence may promote to observed. Existing visited/surveyed and first/last visit events stay intact. Only actual B2 movement creates visit/travel history.
- Added GeographicFact variant npc_description exact {kind:"npc_description",subject:Ref,location:Ref,name:String,occupation:String,visibility:"player",evidence:String}. Location must be the current resolved location and evidence explicitly local; role/name introduced together. New NPC gets engine ID, descriptive_only/public payload, source link and no stats/attitude/quest; existing disclosed NPC reused with exact name/role/location. No relocation, mechanical relationship or remote NPC creation. Other NPC/quest records remain read-only unless separately established by trusted local systems.

## Narration and creativity
There is no reliable general semantic proof of arbitrary free-form LLM prose in this runtime. Default automatic path persists the verified public receipt outcome, accepted geographical/NPC statements and a bounded static sensory grammar; candidate prose outside the grammar is not presented as an authoritative event. Conflicts suppress raw candidate prose; accepted independent facts and audit still commit together. Optional coordinator.prose_reviewer is a trusted LOCAL callable for independently reviewing the exact candidate+facts+receipt; it is never sourced from Gemini or automatically treated as player consent. Only a clean plan and true local review allow full prose; reviewer must independently check agency, mechanics, canon, disclosure and audience, including omitted facts. This is not a complete unrestricted creative semantic verifier; broader free-form dialogue/description and optional geographic metadata need further reviewed support, not fake acceptance. Ordinary supported facts are automatic, not a per-detail player prompt. No mechanical adjudication is delegated to this reviewer. Existing B2 trusted local ruling interface unchanged.

Already migrated older worlds get idempotent backfill on explicit bind/migration when idle; pending receipt revision is never changed. No schema version bump, no changes to master, raw legacy coords, inventory or original opening event. Never migrate from map tab or menu listing.

Original opening NPCs verified from committed opening text. Existing quests require explicit public:true and source event; nonpublic records stay local. No generated quest. Relevant IDs prioritize current/direct connections and provenance from local narration/source relationships/routes, with nearby established positions and parent/region; bounded queries, not whole DB. Earlier relevant location history is available beyond the recent-event window, source event IDs retained. Existing private dm_geography remains local and is not serialized wholesale to Gemini. Context remains bounded; relevant facts beyond bounds or unrecognized synonyms may require clarification; no semantic fuzzy identity guarantee. Public aliases/relations/routes and map-only visible projections preserve privacy. MapView v1 function, query constants and typed_rows byte-identical to A2 checkpoint 959705e; no renderer edits or merge in B4. A2 consumes same map keys and precision/discovery semantics.
