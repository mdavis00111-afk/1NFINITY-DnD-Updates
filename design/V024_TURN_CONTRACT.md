# P4 draft — typed turn interface (V024 Task 04)
Status: design contract only, not a turn controller, not a schema migration, not a gameplay feature. Review/approve at P4. Existing v0.0.23 opening path remains separate at turn zero. The v0.0.24 workspace composer stays disabled; manual dice remain informational. No new RAW mechanics are specified here.

## Authority and types
GDScript typed DTOs (future RefCounted classes or validated Dictionary boundaries) with explicit schema version "1", strict field/type/enum/range/size checks. JSON transport is untrusted; numbers must be finite and integral where required, no silent coercion or unknown keys. UUIDs are engine-owned 32 lowercase hex; catalogue IDs use canonical category/id and edition; event IDs and revisions nonnegative integers. Null is explicit absence, not zero. All packets carry a locally generated request_id (unique per provider attempt); engine-owned turn_id persists across retries of one accepted action. Envelope identity fields are checked exactly, never used to select a database on their own. No arbitrary SQL, file paths, executable text, credentials, or state patches from AI.

Nested proposed types (review exact handler catalogue during P4): EntityRef {kind:enum(actor,location,item,spell,feature,object), id:String}; RuleRef {category:String,id:String,ruleset:String,revision:String}; EventRef {id:int,turn:int,kind:String,text:String}; ActionIntent {handler_id:String, target_refs:Array[EntityRef], reference_refs:Array[RuleRef], intent_text:String}; handler-specific arguments require a registered typed schema before that handler is enabled. No open-ended effect/dice fields in proposal. SceneSnapshot/ActorSnapshot are engine-owned versioned projections of authorized current location, known entities, actor stats/resources/inventory and necessary combat/time state; exact fields defined by supported handlers, not arbitrary DB dumps. RollReceipt {roll_id:String,kind:String,sides:int,values:Array[int],modifier:int,total:int,target:int/null,result:enum}; engine-only and may require extension for advantage, multiple dice groups and other RAW cases. ActionResult and EngineEffect are discriminated unions registered per implemented handler; no generic freeform patch. FactProposal {kind:enum(local_description,npc_description,relationship_description), subject_ref:EntityRef/null,text:String}; proposal only; any new entity gets engine ID, separate validated domain path; no mechanical attitude or effect implied. No promise these example handlers or fields exist now.

## Lifecycle / isolation
1. GUI submission only when explicit controller is bound and campaign snapshot valid; disable Send while pending. Keep draft on rejection; no fake committed player message or AI rolls. Manual dice never enter TurnContext.
2. Controller opens one consistent read transaction in the selected campaign DB, verifies campaign/actor/revision/visibility, looks up canonical rules via catalogue and parameterized SQL. Use exact campaign ID, never master character or other campaign memory. Close read before network. Freeze request context, profile and prompt version for that attempt. No SQL transaction across network.
3. Rules-Check receives only relevant rule records and typed intent; saved Interpreter/Brief settings may be adapted after review, but cannot replace mandatory authority. Missing rule/data or unsupported handler returns explicit unsupported/clarification, not fabricated rule, no mechanics or state writes. Validate response envelope, action keys and reference membership; recheck snapshot revision and preconditions under write transaction. For genuinely ambiguous action ask player; do not force an arbitrary choice.
4. Godot builds plan and runs rules/dice exactly once for accepted logical turn; in single write transaction validate revision, persist actor/inventory/world effects and immutable receipt + event(s) + turn/revision advancement with unique turn_id. Future migration must enforce durable uniqueness/compare-and-set before enabling composer. Failed transaction rolls back; if commit acknowledgment lost, reload by turn_id before retry; do not reroll a committed turn. No current schema changes.
5. Only after receipt commit, generate NarrationContext; preserve committed mechanical facts even if model fails. Provider request IDs scoped to originating campaign, controller generation and turn. Reject stale, canceled, duplicate, wrong-campaign or wrong-revision replies. On failure, show deterministic receipt summary/pending narration, allow retry from persisted receipt only (no mechanics replay). A canceled navigation invalidates callback; committed results remain on disk. Do not allow new turns to overwrite or reorder pending narration; decide queue policy in P4.
6. Validate narration/fact proposals, persist approved narrative event once (unique turn_id + phase) and accepted non-mechanical facts in a guarded transaction, then refresh gameplay_view. Unverified prose must not be treated as world fact; use engine-generated mechanical summary separately; semantic contradictions cannot be solved by JSON alone. If a fact would require mechanics, defer to a later validated action. Reopen/retry from committed log. No change to global/master player.
7. Provider errors: bounded retry/backoff for transient network/429/503 only if configured and no duplicate action; model fallback only to user-approved discovered models supporting required structured response; no silent downgrade to unvalidated prose. Authentication/config errors stop. Preserve provider safeguards. Never log credentials or private campaign packets. Measure input/output tokens, latency, error codes locally without raw prompts; retrieve bounded relevant context, stable IDs and summaries derived from committed events, not entire save history. Existing live transport has manual retry/model selection, not these future features.
