# B3 — Gemini turn coordinator, source contract v1
Branch feature/p3-turn-engine. Builds on B1 and B2, not a published or runtime-certified game. No GUI composer activation. Existing v0.0.24 opening/Settings/GUI are preserved. Read TURN_WORLD_CONTRACT.md for B1/B2 exact DTOs and authority. No new mechanics or schema.

## Local callable interface
Instantiate game/turns/turn_coordinator.gd as a child Node for one active campaign; only a trusted local controller/UI adapter may call its methods, never provider tools. No simultaneous mechanics writers; B4/lead must ensure single ownership. state_changed(Dictionary) signals public phase/status only; schedule mutating calls after signal returns. view_state() supplies campaign_id, actor_id, turn_id, revision, phase, status_text, committed_player_text (empty until receipt exists), mechanical_summary (engine-generated), retry_allowed. No uncommitted AI prose, raw token or private world packet. The UI should not bind the composer until local adjudication, B4 reconciliation, Windows migration and full QA acceptance exist.

- bind_campaign(id) explicitly runs B1 migration/backup then snapshots actor/revision; if a pending committed turn exists, restores its original receipt/input and phase pending_narration; otherwise idle. No automatic network request on resume. If switching while an in-memory receipt is unresolved, reject until reconcile/explicit abandon. No implicit migration by Map/menu.
- submit(text) accepts nonblank <=2000 chars, current campaign only, creates logical turn ID and freezes token. One action at a time. If a committed narration is pending, restores it instead of accepting a new action. Sends Rules-Check with identity, bounded player text, projected actor/inventory, relevant visible geography and canonical catalogue summaries. Each attempt has a new request ID, one transport Node. Only registered B2 handler proposals permitted; existing B2 validator checks exact shape, reference membership and revision; travel additionally restricted to offered current routes. Clarification/unsupported returns a status, no log/dice/write.
- approval_request() only in awaiting_local_approval returns {campaign_id,actor_id,turn_id,expected_revision,player_text,action}. Trusted local adjudicator must independently verify consent, challenge/DC, circumstances, timing, features, route/terrain/hazards/supplies, etc., using B2 requirements. approve(local_approval) accepts the exact B2 approval envelope; never copy provider fields into ruling. No automatic local adjudication is invented. This is an explicit integration dependency, not player automatic success. Reject or ask clarification when unresolved.
- resolve_local uses one resolver instance; B2 validates, rolls and commits exactly once. Player text is optional additional field in existing mechanical_receipt event JSON (not MechanicalReceipt DTO or schema change); original text persists with receipt/event/revision. B2 prepared retry retains original text. receipt_by_id returns player_text (empty for legacy receipts without it). Read committed receipt before narration, validate supported nested shape for projection, no post-state recomputation or reroll.
- After successful commit, reload pending receipt + current revision, retrieve relevant geography, send Narrator request. Use NARRATOR.build with existing editable Narrator, current campaign maturity profile and immutable phase/authority, selected Gemini settings unchanged. Narrator receives committed receipt projection (no hidden DC/geometry), original player text, public canon/events and actual travel. Candidate reply exact identity + text, bounded 12000 chars. Separate geography request extracts facts with exact evidence excerpts, no AI movement, persistent IDs or absolute geometry. Geography reply exact B1 GeographyProposal, source_event_id=null, visible existing IDs or local keys only; reject private references, invalid shapes/evidence and coordinate/point invention.
- reconciliation_bundle() returns private {campaign_id,actor_id,turn_id,expected_revision,receipt,narration,geography}, only in reconcile_pending. B4 must verify matching pending receipt/revision/identities, semantic consistency, provenance and all local/known refs, handle conflicts, validate disclosure, then commit approved facts/audit + narration/event/pending clear atomically. New place/route IDs and coordinates only from B4 validated reconciliation. No proposed movement, time, mechanics or trusted approvals. B3 does not write geography; nonempty proposals must wait for B4. If facts are empty, interim accept_reviewed_text(exact_bundle) is a trusted local text-only boundary: caller must independently review prose against receipt, known world, audience and agency. JSON shape is not semantic review. Never auto-call from provider callback. confirm_reconciled() verifies actual persisted narration event and cleared pending turn; B4 calls after its own transaction.
- retry(): Rules-Check failures resend same logical ID/new request, frozen token must match; mechanics_retry looks up receipt first, reuses B2 in-memory prepared result if uncommitted; pending_narration/narration_failed restarts from durable receipt only; geography_failed reuses candidate with new request; reconcile_pending checks committed acknowledgment (B4 must explicitly retry reconciliation). cancel(): before mechanics retires provider and discards uncommitted proposal; after mechanics retains pending receipt and reloads; refuses cancellation while mechanical resolution/acknowledgment unresolved. abandon_uncommitted() explicit local action after successful lookup proving no committed receipt; never abandons committed turn. Closing/reopening recovers committed receipt, not in-memory uncommitted roll; no visible uncommitted roll. A failed/unacknowledged commit must be looked up before allowing another logical turn. No SQL transaction spans network.

## Context and privacy
WorldStore.dm_geography remains local; public_context(id,related_ids) performs relevant-ID bound queries, not global alphabetic map page. Uses current and bounded related locations selected by B1, visible public place/alias/relationship/route/region, actual recent travel, committed opening/recent public narration and starting legacy public facts. Public IDs only; unknown positions preserved. No private descriptions, NPC/quest payloads without disclosure metadata, secret IDs, raw actor payload, settings keys, other campaign or master data sent. Original opening prose supplies already-disclosed NPCs; richer NPC/quest memory and authorized private-to-DM disclosure await B4. Current projection bounds 24 relevant locations, 24 routes/relations/travel, 96 aliases, 12 recent events plus 2 opening events, 48000 chars scene, 120000 total prompt; fail safely when oversize. Current actor inventory projected first 128 only; local mechanics always uses complete normalized token. No inferred coordinates, no hidden-route geometry. Existing legacy opening world_facts treated as public as in B1; B4 must not store private facts in that legacy payload.

## Provider and failures
Existing Gemini model discovery, API key, selected model and provider safety defaults retained. generate optional max_chars/output_tokens/temperature; prior callers unchanged. B3 uses application/json + responseJsonSchema, complete STOP only, exact schema/identity, per-phase output tokens 2048/4096/8192 and bounded 65536 chars. Manual retry or user-selected alternative model, no silent fallback, no unstructured prose fallback. Provider failures surfaced as generic status; no raw provider error or credentials in player view. Separate cancellation and generation epoch rejects late/duplicate/cross-campaign responses. No automatic quota-spending retries; explicit retry only. Current model structured schema compatibility remains unverified. No live provider test run. Existing editable Narrator preserved; Scene/Interpreter/Brief/Write-back/NPC settings remain unchanged and not silently activated.
