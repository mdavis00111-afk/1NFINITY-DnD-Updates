C1 projection withheld rather than claiming unknown slots empty. Reconcile using equipment_store.reconcile_legacy_slots with a locally verified assignment. Restore the verified backup with the game closed if rolling back to an older incompatible writer; do not use an old build to mutate a migrated campaign.

Existing actor payload and legacy inventory remain compatibility mirrors. Item instances/assignments are C2 ownership authority, with atomic mirror updates; world_state.revision is sole canonical revision. C3 must guard and update mirrors within the same transaction when adding mechanical effects. All mutation entrypoints require an independently trusted local ruling where specified; the boolean local_review and clearance dictionary are NOT proof of authorization from a provider. Never bind an AI-generated boolean or clearance directly. C2 local administrative/context and inventory operations advance revision, not a fabricated mechanical turn or elapsed time; C3 owns rules, action timing, receipt integration and unsupported-action policy. No independent B2 controller calls while a C2 request is adopted. No combat outcome authored by C2.

## Request and settlement
Mutation envelope: {schema_version:"2",campaign_id,actor_id,expected_revision,request_id,kind,args}. IDs 32 lowercase hex where campaign/actor/request IDs required; definition/template IDs have separately validated stable strings. Request ID once only: exact replay returns durable stored result, different contents conflict, stale or pending requests reject. One atomic transaction guards campaign/actor/revision/inventory, inserts event, settlement, effects and increments revision. No-op existing identity reuse settles against original event without fictional revision. Query settlement by exact request ID after ambiguous acknowledgement. No resubmission under a new ID until settlement resolved.
gameplay_session.adopt(id,request,turn_id) accepts unchanged v1 C1 intent envelope after trusted validation, persists accepted_pending; settle_adopted(id,request_id,status,local_no_prepared=false) verifies committed B2 receipt/narration or trusted cancellation and no prepared receipt. C3 must wire adoption/settlement and ensure B2 respects C2 pending state; C4 must not activate controls until tested. Read-only inspections do not mutate state.

## Local write methods (exact args)
* actor_generation.generate(id,request,local_review=false): actor_generate args generation_key, template_ids, existing_actor_id (nullable), kind, name, occupation, location_id, visibility, sheet_visibility, source_event_id, possessions, coins, attitude. Canonical SQL first; reviewed core batch fallback only if missing; gaps explicit. Fixed stats not randomized; Godot selects from approved template options, generated names and stable identity. Existing descriptive NPC upgrades only with matching identity. Possessions are approved contextual choices, not assumed from actions or natural weapons. No generic fabricated level/class/ability progression. Stored immutable stat block and actual sheet plus inventory; private sheet unless independently disclosed.
* loot_store.define_custom: define_custom args definition, source_event_id, official_equivalent_id (nullable). Typed attributes include category/name/description, unit_weight_lb, cost_cp, properties, charges/attunement and optional mechanical_attributes (damage dice/type, armor_class_base, range_feet, physical_options). Exact validation in item_catalog.gd. Custom proposed values do not grant executable effects. Official equivalent reused, conflicting existing definition rejected. define_official args category,catalog_id,source_event_id.
* loot_store.reveal_discovery: loot_discover args source_event_id,location_id,name,items,coins. Trusted committed local source, one container per source. Item quantities positive and actual known definition; no automatic pickup.
* loot_store.reveal_outcome: loot_outcome args source_event_id. Future combat phase must author eligible committed outcome with actual recoverable instance IDs, source actor/encounter and location, verified outcome status and access. C2 only consumes it; no combat, death simulation or automatic transfer to player. Disposable fixture is not live combat. One recoverable container per eligible source actor.
* loot_store.pickup: loot_pickup args container_id,source_event_id,items:[{instance_id,quantity}],coins:{cp,sp,ep,gp,pp}; loot_take_all args container_id,source_event_id. Entire requested transfer succeeds or fails; no automatic partial award. Same location, visible eligible container, actual quantities, weight/capacity and charge/attunement rules checked. Whole retains ID, supported partial stack splits into new ID and transfer history. Mirror + currency + container closure + settlement atomic. Unknown capacity/weight fails closed.
* loot_store.drop: item_drop args instance_id,quantity. Underlying reviewed transfer only; unequipped/non-attuned, stable whole ID, recoverable container at current location.
* story_store.update_story(id,request,local_review=false): story_update args record_id,identity_key,kind,title,description,status,visibility,certainty,location_id,parent_id,source_event_id,progress_current,progress_max,participants. Kinds overview,situation,quest,objective,relationship,animosity,repeat_offender,faction,debt,promise,unresolved_event,circumstance. Fixed overview/situation keys; public/private and fact/rumour/attitude distinct. Existing quest/objective lifecycle validates progress, completion and local acceptance; immutable history and participant references. No forced quest. Legacy unproven records retained, not promoted.
* equipment_store.reconcile_legacy_slots: reconcile_legacy_slots args assignments (verified existing choices only, no equip effect). record_party_membership: party_membership args member_actor_id,status,source_event_id. Reviewed local outcome only, not teleport/control.
See exact nested checks in each service. Clearance is constructed by trusted local code with scope and matching identities/revision; provider has no direct write entrypoint. Equipment, spell, resource, rest, checks, action timing, multi-step and supported effect handlers are C3 work, not implied by persisted schema.
