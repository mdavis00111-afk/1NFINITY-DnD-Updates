## 1. Authoritative read model required from 03 / C2
Extend the existing campaign_store.gameplay_view() dictionary in the SAME committed, player-visible, revision-consistent SQL snapshot. Do not combine actor data read at one revision with a later turn snapshot. Existing campaign.id, campaign.actor_id, actor.id and all actor/inventory/locations/quests/events fields retain their established identity and semantics. Legacy stacks are catalogue item_id + quantity, NOT stable individual item instance IDs; the C1 legacy view is inspectable but cannot dispatch state-changing requests. No fake instance, hand, quantity, coordinates, resource, or slot assignment.

Add required interaction dictionary:
- schema_version: "1"; campaign_id, actor_id: exact 32 lower-hex persistent IDs matching existing view and each other; revision: nonnegative integer.
- phase: idle | busy | awaiting_decision | retryable | blocked; pending_turn_id, active_turn_id: nullable 32 lower-hex logical turn IDs. supported_intents: array of the registered kind IDs below, provided by controller, not inferred from the UI. Optional status_text: public status only.
- settled_request_id: nullable 32 lower-hex request ID. settled_status: null when no settled_request_id, otherwise accepted_pending | committed | rejected | cancelled. Only publish matching settlement when controller adoption or terminal outcome is established, including after unknown acknowledgment; accepted_pending means acknowledged active request, NOT committed effects. Phase remains non-idle when action/narration/decision outstanding. Do not advance revision merely for view/presentation changes.
- inventory_instances: array of {instance_id:32 lower hex stable owned instance/stack ID, definition_id:stable official/custom ID, name:String, description:String, quantity:positive integer, equip_options:Array}. Optional disclosed unit_weight_lb (number/null), public_warning, charges, attunement_status (unattuned | attuned | not_required | unknown) and other reviewed display attributes. C2 owns custom definition, quantities, split/merge identity, actual weight/charges and provenance. C1 does not assume custom weight or mechanics from a template.
- equip_options per item: [{slot,grip,available:bool,warning:String,replace_instance_ids:[owned instance IDs]}]. Distinct (slot,grip) options, no duplicate displaced ID or self-reference. Include physically compatible owned candidates even if unavailable, with explicit explanation. Grip enum worn | one_handed | two_handed. Backend provides physical compatibility, available quantity, hand occupancy, proficiency consequences, attunement, action timing/action economy, and any other necessary warning/choice. C1 shows offers only; does not derive legal attacks or recalculate AC. A swap is ONE intention with all displaced IDs, including both hands or shield when applicable; never a sequence of independent optimistic writes.
- slot_assignments: dictionary with EXACTLY all twelve keys head, cloak, body, hands (gloves), feet, neck, ring, accessory, belt, shield, main_hand, off_hand. Value is actual owned instance ID or explicit null for established empty slot. A shared two-handed/shield-hand identity may occupy more than one logical slot; C3 resolves conflicts and timing atomically. No implied mechanical limit from UI slot count. Existing actor.equipment definition-ID display and derived actor statistics/weight must remain consistent with authoritative instances and assignments for the full character sheet.
- spell_options: [{spell_id,source,slot_level:integer 0..9,available:bool,warning:String}]. Distinct spell/source/level; source enum class_cantrip | racial_cantrip | known | prepared | always_prepared. Zero level for explicitly offered slotless cast (including cantrip), not a free-cast assumption. Actual class/racial/pact/ritual/slot and timing constraints are C3-owned. preparation_options: [{spell_id,kind:spell_prepare | spell_unprepare,available:bool,warning:String}], distinct spell/kind; includes valid class-list offers even if not already known. C3/C4 must provide explicit decision flows for targets, ritual choice, components, concentration, rest-time preparation and any unresolved consequential choice. Null target is unselected, NOT self-target.
- public_quests: [{id:32 lower hex,title:String,description:String,status:String,source_event_id:positive integer}] already disclosure/provenance-filtered by C2. No private payload or arbitrary raw JSON. Legacy quest journal uses existing B4 public_context(campaign_id,[]) for bounded disclosed current-location quests; if unavailable it reports unavailable, not hidden/empty world. Campaign-wide public quest projection required from C2.
- Optional party_members: disclosed companions excluding controlled actor [{actor_id,name,portrait,level,hp_current,hp_max}], actual IDs, level/HP nullable. Optional party_candidates: [{actor_id,name,available:bool,warning:String}] real disclosed actors, distinct from player and current members. No candidate or member is invented. Existing Add slots remain unavailable without an explicit eligible candidate and party_add capability. Four-card layout is not a mechanical party size limit.
- Existing locations must be player-visible same-revision records (stable id, public name etc.); a travel target must be present there and in the same-revision MapView, and distinct from current party location. B1 MapView v1 units/precision/discovery unchanged. Actual route/transition/encounter clearance owned by controller.
- Existing actor fields (HP/AC/initiative/speed/abilities/saves/conditions, skills, level, XP, coins, carried weight, resource max/spent and spell slot maximum/spent) must reflect committed state. Do not fill unknown values as zero. C2 must supply normalized public committed events of kinds campaign_created, player_action, mechanical_summary and narration, with event order/turn/text. Never place candidate prose, raw private receipts, pending rolls or provider data in events. The old view currently projects creation/narration only; new event kinds require C2.

C2 must also supply scoped, validated definition and instance queries, public quest/party membership, actual authoritative resource and spell state, encounter/action timing and the durable controller identity/revision/request mapping. Existing B1 add_annotation stays separate, noncanonical. Annotation deletion/free-position notes need a reviewed separate B1 interface; no competing writes.

## 2. Single typed intention envelope
game/gameplay/ui_intents.gd implements an executable local guard. Every dispatched gameplay intent is exactly:
`{schema_version:"1", campaign_id, actor_id, expected_revision, request_id, kind, args}`
request_id is a fresh 32 lower-hex local UUID-like ID for one user submission. expected_revision is the accepted interaction view revision. This is player intention only: no DC, roll, effect, timing, coordinates, SQL, code, success, AI plan or approval. Controller independently revalidates all data, ownership, exact slot/displacement, state/revision, action economy, target visibility, rules and capability. Reject unknown fields; no permissive raw player text as engine commands.

| kind | exact args | Required authority |
|---|---|---|
| equip | instance_id, slot, grip | 03 instance/slots; 02 equip rules/time |
| swap | instance_id, slot, grip, replace_instance_ids | 03 atomic slot/instance update; 02 conflicts/grip/time |
| unequip | instance_id, slot | 03 assignment; 02 timing |
| item_use | instance_id, quantity, target_id (nullable) | 03 charges/quantity; 02 supported effects/targets |
| item_drop | instance_id, quantity | 03 transfer/location/accounting; 02 legality/time |
| attune / unattune | instance_id | 03 attunement state; 02 eligibility/rest |
| spell_prepare / spell_unprepare | spell_id | 03 known/prepared state; 02 class/rest eligibility |
| spell_cast | spell_id, source, slot_level, target_id (nullable) | 03 resources/state; 02 casting/effects/concentration |
| skill_check | skill_id | 02 challenge/RAW ruling and dice, 03 receipt |
| ability_check / saving_throw | ability | 02 contextual ability/save rules, 03 receipt |
| rest | rest_kind: short or long | 03 clock/resources; 02 eligible rest and effects |
| resource_use | resource_id, quantity | 03 resource account; 02 feature rules/effects |
| level_up | {} | 03 XP/advancement state; 02 eligibility and required choices |
| quest_interact | quest_id | 03 disclosed quest state; 02 supported consequences; discuss/pursue only |
| party_add | member_actor_id | 03 actual actor/membership; 02 consent/control/time |
| travel | destination_id | 03 known world, routes, revision; 02 travel rules and committed movement |
| chat | text (original unmodified, nonblank, <=2000 chars) | 02/03 typed local adjudication boundary, later 04 semantic pipeline in C5 |
| retry / cancel | turn_id | Existing B3 lifecycle must be bound by C4; same active logical turn, no reroll |

All identity arguments are real IDs in appropriate current projection, not UI indices or display labels. Quantity integer positive, <= owned/remaining where recorded. No direct character-stat edits. Unselected targets explicitly null; C3/C4 must agree versioned decision-response and choice/target DTOs for multi-step actions rather than choosing on behalf of player. C1 does not invent those mechanical outcomes or a second decision store.

## 3. Binding, error and refresh protocol for C4
game_workspace.configure(snapshot,metadata,on_leave,on_settings,on_retry,is_pending,error="",intent_handler=Callable()). Production caller unchanged and unbound. The legacy action_requested signal is retained for compatibility but never emitted. Only the explicit handler goes through ui_intents.request. Never bind to raw provider calls. Existing opening generation/retry is a distinct existing callback, not turn retry. B1 annotation save remains a separate existing scoped note API.

- Adapter permits ordinary intentions only in idle with no pending receipt, supported kind, valid same-identity view and no outstanding request. Retry only in retryable for active_turn_id; cancel only if capability and an active turn in busy/awaiting_decision/retryable/blocked. Existing opening/data-error guard also applies. Controller must enforce the same guards even after closing/reopening.
- Handler returns {ok:bool,request_id:String,message:String} synchronously as delivery acknowledgment (not receipt). true means accepted for processing only; false must be definitive pre-write rejection. Unknown/malformed/mismatched response locks the outstanding request until controller reconciliation. No automatic retry or optimistic display change. Do not dispatch unrelated new intent while locked. Controller records idempotency mapping to actual logical turn and receipt.
- Trusted controller feeds fresh full committed view to game_workspace.apply_authoritative_view(snapshot), deferred until request callback returns. Identity mismatch, invalid/incomplete packet, decreasing revision fail closed; fresh valid view needed. An unrelated refresh never unlocks an outstanding request. Matching settled_request_id releases request lock, but controller phase/pending guards remain authoritative. accepted_pending permits controller-supported cancel/retry, not another ordinary action. Only committed terminal settlement clears matching chat draft. Rejected/cancelled/ambiguous text preserved for user; do not auto-resubmit. C4 must retain settlement history/identity so matching chat settlement can be reconciled even after another control action. No user-facing claim of success until committed view. Rebuild existing controls from actor/instance read model; preserve selected tab/filter/item when available and manual informational dice, chat draft. Stale popup closes on refresh. C4 handles local draft retention when switching windows and controller-authorized save/exit/settings, including pending committed narration. Existing leave/settings blocked during unresolved UI acknowledgment.
- Map configure(id,title,handler,expected_revision): only bind when travel capability currently available. Same MapView revision plus visible destination; adapter validates exact packet identity and destination membership; acknowledgment and lock, never changes party position. Map opens/closes/refits on committed state, not intention. Existing annotations unchanged.
- Real controller binding, mock-provider end-to-end tests, actual action decisions/targets, full handler availability, native GUI/SQL/Windows acceptance and C5 semantic Gemini work are not C1 completion. Do not activate live composer/travel in C1/C2/C3.
