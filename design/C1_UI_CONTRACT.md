## Authoritative view (C2 must supply)
Extend existing gameplay_view result with interaction in the SAME revision-consistent player read transaction, not a separate race-prone read. Exact semantics:
- schema_version "1", campaign_id, actor_id (existing 32 lower hex IDs), revision nonnegative integer, phase idle/busy/awaiting_decision/retryable/blocked, pending_turn_id and active_turn_id nullable real turn IDs, settled_request_id nullable UI request ID (only when explicitly settled/reconciled), supported_intents array of supported kind IDs. Controller owns phase and capabilities; never enable by UI inference. Do not expose raw private state, provider packets or approvals.
- inventory_instances: [{instance_id:32 hex stable owned instance/stack ID, definition_id:official/custom definition ID, quantity:positive integer, name:string, description:string, equip_options:[{slot,grip,available:bool,warning:string,replace_instance_ids:[instance IDs]}]}]. Quantity is total owned units of that instance/stack; C2 split/merge identity rules authoritative. Optional extra public item data: unit_weight_lb, charges, attunement status, proficiency/timing/consequence notes. Equipment slots map canonical slot names to actual instance IDs or null. Body/head/cloak/hands(gloves)/feet/neck/ring/accessory/belt/shield/main_hand/off_hand; two-handed or shield/offhand may share identity where required, C3 resolves conflicts atomically. No new ring/attunement limits invented. Options reflect physical compatibility and actual owned state; C2/C3 produce available and warnings including action timing, armour proficiency consequences, attunement, charges, quantity and hand occupancy. Option replace_instance_ids lists all displaced owned instances (including other hand/shield) for atomic swap; do not split swap into independent writes. Backend revalidates all options; preview not ruling. C1 legacy display shows only catalogue-compatible armor/shield/weapon candidates without mutation.
- spell_options [{spell_id,source:class_cantrip/racial_cantrip/known/prepared/always_prepared,slot_level:0..9,available:bool,warning:string}]. Slot level zero for cantrip or explicitly offered slotless cast; backend supplies actual legal options for prepared/known and racial sources, ritual/pact/slot constraints. C3 must add richer targets, ritual and concentration choice through controller decision flows, no inference from slot totals. 
- Existing actor, inventory, quest, location, events remain authoritative public projection. C2 must project public committed player text/mechanical summary/narration chronology (never raw receipts/private text), condition/resource/HP/AC/weight/spell/coin changes and quest visibility. Party membership currently unsupported; no fake companions. Future C2 party membership/quest/advancement projections extend this contract through reviewed versioning.

## Intent envelope and acknowledgement
{schema_version:"1",campaign_id,actor_id,expected_revision,request_id:local unique 32 hex,kind,args}. args exact keys in ui_intents.gd FIELDS. No SQL, DC, rolls, effect deltas, resolved coordinates, time, or success assertions. User text retained verbatim for chat. C3/02 validates identity, ownership, actual rules, timing, action economy, conditions, resource limits and pending revision; C2/03 owns atomic persistence and receipts. Retry/cancel refer to controller active_turn_id; never create new mechanics from retry. Controller callback returns {ok:bool,request_id,message:string}; true means accepted for processing, NOT committed; false must be definitive rejection before any mutation. Unknown ack holds guard until reconciliation. Do not unlock on a random newer view: controller publishes settled_request_id matching outstanding request. C4 feeds fresh committed full view via workspace apply_authoritative_view after controller callbacks return, not optimistically patching controls. Reject cross-campaign/actor and decreasing revision. Backend must enforce identity/revision/idempotency even if UI closed/reopened. No automatic retry. For multi-step selection or targeting, C3/C4 supply a structured decision response; do not choose on behalf of player. 
- equip {instance_id,slot,grip}; swap same + replace_instance_ids; unequip {instance_id,slot}; attune/unattune {instance_id}; item_use {instance_id,quantity,target_id:null or visible actor ID}; item_drop {instance_id,quantity}; spell_prepare/unprepare {spell_id}; spell_cast {spell_id,source,slot_level,target_id}; skill_check {skill_id}; ability_check/saving_throw {ability}; rest {rest_kind:"short"/"long"}; resource_use {resource_id,quantity}; level_up {}; quest_interact {quest_id}; travel {destination_id}; chat {text}; retry/cancel {turn_id}. Null target is unselected, not self-target or default. Travel adapter requires same MapView revision; controller determines route/clarification and commits movement only via existing authority. Quest intent means discuss/pursue, never auto-complete. Character advancement intent asks controller for available choices; no XP writes.
- No direct HP/AC/coins/slots counters editing, no manual dice integration. Manual dice remains informational. Opening generation existing callback remains separate; no provider changes. C4 should only bind supported controller capabilities, leave unsupported controls visibly disabled.
