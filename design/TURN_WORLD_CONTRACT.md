# B1 — turn and world persistence contract v1
Status: source foundation on feature/p3-turn-engine. No gameplay controller, provider or renderer enabled. Read WORLD_CARTOGRAPHY_SPEC.md and V024_TURN_CONTRACT.md; this document fixes the persistence/DTO subset for B2/B3/B4/A2. All IDs are 32 lowercase hex generated by Godot except proposal-local keys and catalogue IDs. All DB access is scoped by an already selected local campaign ID, never a provider envelope.

## Storage, migration and units
- Existing per-campaign user://campaigns/v1/<campaign_id>.db, meta.schema=1 and eight legacy tables remain. Separate additive meta.world_schema=1; world_migration.gd ensure(id:String)->Dictionary {ok:bool,migrated:bool,backup?:String,error?:String}. Call explicitly before B2 controller is bound, not during menu listing or old GUI startup. New and existing campaigns share this migration; no eager modification of saves. On first migration: read exact metadata, SQLite VACUUM INTO a unique .bak in same directory (SQLite >=3.27), verify backup integrity/metadata/schema, then one BEGIN IMMEDIATE batch with exact metadata and absent-marker guard, additive DDL, seed and marker. Failure leaves original transaction rolled back and backup retained. Backup is consistent at snapshot time, not a promise of later concurrent writes; run migration while campaign closed to other writers. Existing actor/inventory/log/location payloads and raw legacy x/y remain untouched. Existing .bak excluded from roster; no auto restore/delete. Old executable can read base schema but does not enforce new privacy/revision; do not resume world-enabled saves in an old build without a validated backup/rollback plan. Windows SQLite VACUUM INTO support must be verified before activation.
- world_state singleton campaign_id (also world_id), revision:int, turn_number:int, pending_turn_id:String/null, elapsed_seconds:int/null. Initial revision 0, legacy turn retained, elapsed time unknown. No artificial in-world date. Turn revision counts canonical writes, not elapsed time. B2 must establish clock explicitly via approved rules before known elapsed time is accumulated.
- locations.id,parent_id,kind,name,x,y,payload remain authoritative base row. world_places adds metadata (region_id, precision, uncertainty_miles, elevation_feet, terrain, footprint JSON, population, occupancy, asset_id, private description/notes, public_description, source_event_id). One row per existing place. Unknown/provisional position has no usable x/y: old stored raw numbers are retained but hidden. Approximate/surveyed position requires accepted finite x/y plus explicit nonnegative uncertainty_miles. New geometry uses miles, x east/y north, Godot screen y inverted; arbitrary established local origin, not forced origin. One coordinate plane per campaign for now; regions partition/nest that plane and do not imply separate origins. If disconnected geography has no established relation, keep position null; no implied distance between regions. Coordinates bounded only for storage sanity to +/-1e12 miles, not a designed world edge. Elevation feet. Population null means unknown, not zero; occupancy unknown independent of discovery. Footprint is optional ordered polygon JSON; B4 validates accepted shape and uses same precision. Terrain/route/movement vertices use separate ordered points, max 256 per geometry, no fabricated geometry or straight-line fallback. A2 must not draw unresolved coordinates or use legacy raw x/y.
- terrain_regions/terrain_points (nested region, precision, public/private descriptions); world_routes/route_points (existing named route endpoints, kind, precision, distance nullable); geographic_relationships (from/to/kind, direction/distance nullable, precision, visibility, evidence event); location_aliases scoped to location ID, not globally unique; world_links connects a location to actor/quest/encounter; geography_audit records request/source-event/proposal-index uniqueness, accepted/conflict/deferred/rejected, subject and detail. Foreign keys and indexes in world_schema.sql. B4 owns domain vocabulary, asset whitelist, conflict handling, acyclic parents, consistent reference resolution and all accepted descriptive writes. Do not update canonical geography by freeform SQL or an AI patch.
- world_discovery has exactly one location/route/region FK, one row per entity, status unknown/reported/observed/visited/surveyed and visibility player/private, source first event and last visit. Only player non-unknown is renderable; hidden absence is not uninhabited. A new deterministic committed start already occupied by actor is visited (name only, no x/y). Other legacy places remain undisclosed; turn-zero opening path is unchanged; B4 must reconcile opening facts and new locations under the same revision discipline. Public descriptions are explicitly separate; shared map metadata (names, kind, precision, public coordinates, terrain, population/occupancy, asset IDs, route/region points) must be player-approved before visibility is set. Private details only in private fields/records. Public route/region geometry may not encode undiscovered secret waypoints. Discovery proposals cannot mark visited/surveyed: visits from actual movement, surveys from later resolved exploration. Never downgrade or erase established knowledge silently.
- world_annotations separate player note at visible location, 1..1000 chars, actor-local. Not canon, no mechanical effect/revision increment. Refresh map after annotation success.

## Callable interfaces
All returns are Dictionary, ok:false,error:String on failure; no partial write after rejection. SQL bridge string/null values converted by world_dto.gd sql_int/sql_number (no missing -> zero). Existing campaign_store.gd gameplay_view remains compatible without migration; migrated legacy popup reads discovered places only and suppresses unverified coordinates/raw private payload. It retains already player-visible starting facts. Composer remains disabled.

### Mechanical persistence
game/turns/turn_store.gd:
- snapshot(campaign_id:String) -> {ok,campaign_id,actor_id,location_id,revision:int,turn:int,pending_turn_id:String/null,elapsed_seconds:int/null,metadata:String,actor_payload:String,campaign:Dictionary,actor:Dictionary}. Local frozen token only; never send raw metadata/actor payload to provider. Verify active campaign and actor identity, turn consistency and same read snapshot. B2 adds supported rule/inventory/combat preconditions before commit, not raw caller SQL.
- receipt_by_id(campaign_id:String,turn_id:String) -> {ok,found:bool,receipt?:MechanicalReceipt,narration_event_id?:int/null}. Consistent identity snapshot; lookup before resolving and after failed/ambiguous acknowledgement. Never reroll a found turn; compare identity and return prior receipt. If lookup itself fails, retry lookup, not mechanics.
- commit_receipt(campaign_id:String,token:Dictionary,receipt:Dictionary) -> {ok,replayed:bool,receipt:Dictionary}. Receipt exact keys: schema_version "1", campaign_id,actor_id,turn_id,prior_revision:int,next_revision:int=prior+1,resulting_turn:int=prior turn+1,results:Array[Dictionary],rolls:Array[Dictionary],effects:Array[EngineEffect],rule_refs:Array[Dictionary]. Array caps 128, packet <=131072 chars. B1 validates envelope, not nested RAW result/roll schema; engine-only API. B2 must implement registered discriminated result/roll/effect unions, validate rule refs and exact preconditions and extend this transaction for HP/inventory/resources/time effects. B1 rejects all effects except empty array or one resolved movement effect. No arbitrary patch. Caller must never pass AI JSON to commit_receipt.
- Movement effect exact {kind:"movement",segments:Array[ResolvedSegment]} (1..64 contiguous segments). ResolvedSegment exact {from_id:String,to_id:String,route_id:String/null,distance_miles:float/null,elapsed_seconds:int/null,precision:enum,points:Array[{x:float,y:float}]}. Distinct endpoints already persisted; first from_id must equal current location, route if supplied must connect endpoints (either direction). Points empty means no established actual geometry; unknown/provisional may not include points. If supplied, 2..256 points and first/last must match accepted endpoint coordinates, all finite. Engine B2 alone decides actual resolved path, distance/time; not inferred from route existence, DM wording, destination proposal or desired direction. Movement may be relational only. B1 uses exact actor/metadata/revision/pending guard under write lock, inserts receipt event, unique receipt, movement segments and points, actual destination discovery/visit, actor row + actor JSON + campaign metadata position, revision/turn and pending narration in one transaction. Failure rolls back all. Existing elapsed clock stays null if unknown; known clock accumulates only supplied known segment durations, becomes null if duration unknown. No forced precision. No new action, combat or travel rules in B1.
- commit_narration(campaign_id:String,turn_id:String,revision:int,text:String) -> {ok,revision:int}. Text-only already accepted narrative boundary, 1..12000 chars. Checks pending turn and exact current revision. Unique turn_narrations row + narration event + revision advance + pending clear atomically. B4 must extend same transaction for accepted descriptive facts/audit; do not write facts separately then narrate uncommitted data. B3 must validate provider identity/content and do not expose uncommitted prose. If failed/ack lost, receipt lookup finds narration_event_id. No further mechanical turn while pending narration. The existing GUI reads creation/narration only; B3 will integrate player input/committed receipt summary and retry status. B1 does not claim playable chat.
