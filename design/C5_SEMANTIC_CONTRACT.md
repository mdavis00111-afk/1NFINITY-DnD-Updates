# C5 development AI integration — acceptance boundary

Branch feature/complete-gameplay; base 0ddb4d6. C5 is explicit development binding only: instantiate semantic_controller.gd as a Node, call bind_ai(campaign_id, trusted_context_reviewer, trusted_prose_reviewer, optional_test_transport_factory), mount existing workspace. No main campaign-manager activation. Existing narrator_prompt.gd is preserved byte-for-byte. Main settings adds only a prompt handover dialog.

## Semantic pipeline
The adapter uses the selected existing Gemini transport/model, requires complete bounded responses, retires each transport, rejects stale identity/callbacks, at most four calls and eight public enquiries per stage. JSON shape/registry validation precedes writes. Query batches are revision-scoped, capped, deduplicated and returned as data; malformed requests get bounded feedback. Direct UI choices are validated by C3; consequential natural requests receive a second independent interpretation without the first proposal. Matching typed requests, original text/revision and supported deterministic slice are checked locally. This is not proof of arbitrary language equivalence; disagreement blocks. First-level simple human fighter contextual checks with public local source and no proposed circumstances can use proposed difficulty categories; more complex contextual judgments, rests, travel, transfers, attunement and unsupported effects still require a trusted local reviewer. No model-provided accepted flag. Ordinary conversation/observation have no mechanical effect. Ordered plans max four, one subrequest at a time, durable IDs, fresh interpretation after each settlement, no auto-rebase, stop on failure/disagreement. Repeated identical dependent effects need explicit new intent.

Narrator uses existing NARRATOR.build and original creative prompt/authority/maturity; context preserves SCENE, ACTION THIS TURN, OUTCOME, MEMORY, CAMPAIGN LOG, PLOT HOOKS, COMBAT, RECENT OUTCOMES plus actual character, NPCs and rules. AI-selected public enquiries may retrieve older history, geography, item/rule references and story factors. Base context is bounded, no raw SQL/private DB export. Selected interpretation enquiries are retained for that action; direct UI actions use baseline and rules, not a separate AI relevance pass. Standalone settlements use actual source event and result, not fake rolls/turn receipts.

Critical output extraction identifies offers, agency, new effects, disclosure and contradictions; no proposal is clearance. Required mechanical effects are corrected into unresolved proposals or explicitly blocked, not executed post-receipt. Full arbitrary creative prose needs independent trusted review of exact candidate and canon; default deterministic fallback accepts only inert static sensory grammar. This remains a significant C5 acceptance gap: no general automatic free-form semantic proof or production review policy. One bounded correction before preview; user may explicitly settle with verified outcome only if reconciliation cannot finish. Reviewed preview is distinct from committed log; no silent replacement after preview on geographic conflict. B4 standalone narration adds source-linked meta marker and event in one guarded transaction, advances canonical revision without incrementing mechanical turn or creating B2 receipt. B2 adopted path remains receipt-backed.

After narration settlement, C3 story and discovery operations use actual committed event provenance, independent contextual review, distinct durable request IDs, official/custom definition reuse and optional @index links to previously settled definitions. New actors require canonical templates, private stat sheets; discovered possessions remain containers, never automatic pickup. New mechanically consequential DM transfers are not automatically executed. Noncritical world work can be skipped explicitly only after safe settlement recovery. Queue/draft persisted via C4; next input resolves at latest state, no SQL lock across Gemini. Latency instrumentation records local monotonic milliseconds, stage/call and enquiry outcome only, no prompt or key logs. Native response timing remains unmeasured; main-thread SQL still synchronous.

## Prompt handover
Settings local Save/Reset remain unchanged. Narrator Prompt Handover exports saved prompt only with explicit owner consent, base SHA-256, proposed revision, pinned source commit, UTC and summary. Local export path under user://prompt_sharing/exports, not publication. Credential-like text blocked; owner reviews content for privacy. Lead checks repository prompt base and change summary, commits approved prompt-only bundle on coordinated branch and records handover, returns kind=shared with approved source commit. Imported revision must be next and base hash match, no automatic overwrite. Preview shows both local and incoming text, explicit keep-local or replace-local, archive both before write; stale ancestry rejects and original incoming file remains. Offline metadata is not cryptographic proof of Lead authorization; owner confirms source. No Git credentials, config upload or cross-PC sync.
