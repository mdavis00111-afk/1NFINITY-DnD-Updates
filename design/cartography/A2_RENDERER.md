# A2 dynamic atlas integration
Base: d17af456; no live release, schema or mechanical changes.

## Runtime architecture
- `map_model.gd` loads only B1 `world_store.map_view` pages (128 per read; maximum 512 pages, fail closed on changed revision or budget). Independent lists are merged by entity/composite stable key; no partial map displayed. Search uses B1 visible name/alias query. Annotation is the sole permitted write via B1 add_annotation; no erase API. No migration is called from the map.
- `asset_catalog.gd` reads A1 registry, excludes both vintage assets even for explicit asset IDs, chooses deterministic variation by stable-ID SHA-256 and symbol/illustration LOD; no art for an unrecognized kind. The physical vintage SVGs remain in the development branch for provenance; lead must exclude from distribution or replace before release.
- `map_canvas.gd` renders supplied locations, terrain polygons and ordered route/travel geometry. Camera centre is stored as scalar doubles, x east/y north, scale pixels/mile. Screen clip, label overlap suppression, stable LOD and bounded fog texture stamps. Red travel only from committed movement points. Missing positions or geometry remain unplotted. Distances are Euclidean between known points with summed coordinate uncertainty, not route distance. Route distances shown only when stored. Unknown ground hatching is decorative; only accepted public terrain polygons show their established boundary, and all player-visible markers are drawn over the substrate. No claimed visibility area or global explored percentage. B1 lacks authoritative explored-area masks. Toggle fog hides decorative hatch only, never changes visibility.
- `map_window.gd` modal map over gameplay. World overview/region dropdown, zoom wheel/buttons, drag pan, centre party, search (including unresolved names), details, notes, committed history, layer toggles, legend, measurement, full-viewport map mode and restore. Unresolved locations searchable but not centred. Note drafts local to window; only explicit Save annotation persists. Erase disabled, no B1 deletion API.
- Existing gameplay `show_map()` alone opens atlas with selected campaign ID/title. No changes to composer, other GUI or controller. Optional future explicit `intent_handler` receives {kind:"travel_intention",campaign_id,expected_revision,destination_id}. It is unbound in current gameplay; travel disabled. A future controller must validate current identity/revision and translate to its accepted ActionSubmission; callback never resolves movement or changes map state.
- World/regional scale uses one mile plane and known region IDs. Region selection is an explicit visible membership filter, no inferred containment. Future local frames (settlement, building/interior, tactical) need reviewed parent-scoped coordinates and visible DTOs (feet, levels, topology); do not scale world icons into local maps. Current map exposes region drilldown only. B1 Region does not expose parent region relation.
