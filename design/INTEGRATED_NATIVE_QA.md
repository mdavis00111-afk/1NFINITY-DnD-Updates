## A. Pinned bytes and native headless test
Install Git, Python 3.10+ (development-only) and official/owner-approved native Godot 4.7.2 of the correct OS/architecture; record engine --version and executable SHA256 against trusted distribution evidence. Do not substitute Windows executable under Wine for production bridge validation. On Windows use a console-capable engine executable and Windows PowerShell 5.1 with .NET Framework and winsqlite3.dll. Confirm the DLL supports VACUUM INTO (SQLite >=3.27); world smoke must prove the actual operation. No Python runtime requirement for the game.

Clone in an isolated workspace and fetch feature/integrated-qa. Check out the Task 06 runner commit (or later approved checkpoint). Select the exact full source SHA to test, not a moving ref. The runner obtains raw committed blobs via git cat-file, not checkout bytes; verifies Git blob SHA1 and staged bytes, complete inventory, two versions and cartography registry; refuses unsafe/duplicate paths. It never writes to the checkout or live manifest. Default ten suites; assets is a separate optional eleventh requiring authorized local reference/assets next to the standalone engine, never upload that pack.

Commands from checkout root (replace paths; new logs directory for every run):
    python design/tools/run_native_qa.py --repo . --ref 1c700a06f2736500795a8dfdb03efbd84a2468b9 --logs ../qa-byte-audit --audit-only
    python design/tools/run_native_qa.py --repo . --ref 1c700a06f2736500795a8dfdb03efbd84a2468b9 --logs ../qa-native --godot /absolute/path/to/godot
Windows example:
    py -3 design/tools/run_native_qa.py --repo . --ref 1c700a06f2736500795a8dfdb03efbd84a2468b9 --logs ..\qa-win --godot C:\QA\Godot.exe

The Windows runner leaves production sqlite.gd, PS/C# bridge and test scripts unchanged. Linux uses existing disposable Python transport in a copy only, never production-equivalent. Both modify only the temporary project config to a new random custom user directory for import and each suite, redirect relevant environment paths and probe actual user:// before running any suite; abort if it is not fresh. Guarded suites receive exact INFINITY_TEST_USER_ROOT. If Godot generates other files before the probe, or path identity fails, stop and inspect logs; do not weaken safeguards or point at a real user directory. The runner records stdout/stderr, timeouts, version, inventory and report.json. A PASS from this runner means only the selected headless suites/import passed, not Windows deployment, manual UI or release clearance. Run optional assets separately on authorized fixtures with --suites assets. Logs may show local paths; redact before sharing. Use isolated VM snapshots; temporary project is cleaned, unique Windows test profile folders outside temporary root may remain, never delete unrelated user data.

## B. Windows staging, backup, rollback test matrix
Do not test the production updater on a real installation. Use a disposable Windows VM with a known-good copy of the exact shipped launcher/updater and Godot 4.7.2, current published source at 1cc6ea48e8d25a12586a4d1668dc5e7727e0222e, and a second pinned candidate source checkout. Create a fixture character with portrait, campaign with history, settings and custom prompts using the old game; do not use real credentials. Close all processes. Locate actual user:// via Godot probe in the test account; normally %APPDATA%\1NFINITY_DnD_Godot. Backup entire directory offline, including SQLite WAL/SHM files if present, plus install root active-game.txt and previous pointer. Never copy only a live database. Use a new local protected backup directory; robocopy source destination /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /XJ, treat exit >=8 as failure. Inspect for junctions/reparse points and stop if present. Compare SHA256 and relative paths of every file, retain original and backup, keep test credentials out of logs. A verified offline backup is separate from the updater's project-pointer rollback.

For repeatable same-version staging, use a local fixture manifest and local raw files in the isolated VM. Do NOT change channel.json, publish a fake release or modify installed updater code. Export exact git blobs to a local candidate folder using git archive (verify against runner inventory; no checkout CRLF conversion). Build fixture JSON from inventory: channel godot, version 0.0.24, source_commit exact candidate SHA, notes internal QA, files array with path/blob from inventory. Verify expected source bytes. Keep baseline project in game-<32 lowercase hex> and point active-game.txt to it; record its pointer and file hashes. For fresh-install check no previous game/pointer, use existing initial-release.json and verified seed; test network-free with local seed. For upgrade/rollback cases with previous project, invoke unchanged Update.ps1 from a separate test-only PowerShell wrapper that shadows only Invoke-RestMethod (returns local fixture manifest for exact live channel URL) and Invoke-WebRequest (copies exact path under local fixture source for expected immutable source URL; rejects all other URLs). Disable network in VM during fixture runs. This exercises updater code, not real HTTP/TLS. Use -Repair to stage same version without version bump; ExpectedVersion 0.0.24. For restart coverage use the real disposable old game PID, close old game while updater waits; do not kill other processes. Use separate powershell.exe process per test so updater exit code is captured. Example wrapper skeleton below, not executed here; paths and exact SHA passed as arguments. Do not copy wrapper into production.

    param([string]$Root,[string]$Manifest,[string]$Fixture,[string]$Source,[int]$OldPid=0)
    $ErrorActionPreference='Stop'
    $m=Get-Content -LiteralPath $Manifest -Raw | ConvertFrom-Json
    if($m.source_commit -ne $Source -or $Source -notmatch '^[0-9a-f]{40}$'){throw 'Fixture identity'}
    function Invoke-RestMethod {
        param([string]$Uri,[int]$TimeoutSec)
        if($Uri -notmatch '^https://raw\.githubusercontent\.com/mdavis00111-afk/1NFINITY-DnD-Updates/godot/channel\.json\?t=\d+$'){throw 'Unexpected channel URL'}
        return $m
    }
    function Invoke-WebRequest {
        param([switch]$UseBasicParsing,[string]$Uri,[string]$OutFile,[int]$TimeoutSec)
        $prefix='https://raw.githubusercontent.com/mdavis00111-afk/1NFINITY-DnD-Updates/'+$Source+'/game/'
        if(-not $Uri.StartsWith($prefix)){throw 'Unexpected source URL'}
        $path=$Uri.Substring($prefix.Length)
        if($path -notmatch '^[A-Za-z0-9_.-]+(/[A-Za-z0-9_.-]+)*$' -or ($path.Split('/') | Where-Object {$_ -in @('.','..')})){throw 'Unsafe fixture path'}
        Copy-Item -LiteralPath (Join-Path $Fixture $path) -Destination $OutFile
    }
    & (Join-Path $Root 'Update.ps1') -InstallRoot $Root -ExpectedVersion '0.0.24' -GamePid $OldPid -Repair
    exit $LASTEXITCODE

Run each case from the same clean VM snapshot, remove candidate seed or ensure it cannot mask a deliberate failure, capture pointer, old/candidate folders, update.log, import.log, sqlite-smoke.log, smoke.log, game.log and rollback.log; check old restart and backup readability. Verify:
- Clean staged upgrade and first install: exact staged blobs, import, SQLite and both version handshakes, pointer changes only after windowed readiness; prior folder retained; Launch.cmd restarts candidate.
- Corrupt downloaded bytes / wrong manifest hash: updater fails before import/activation; old pointer and folder unchanged, old game reopens when restart flag set.
- Missing required path, duplicate/case conflict, invalid path, mismatched expected version, absent download, locked update.lock, previous PID still active: rejection/no activation, no damage to user data. Lock-held case may not restart old game because it never entered restart phase.
- Correctly hashed synthetic invalid project or wrong handshake: fail import/startup, stop stage process, preserve old pointer. Do not commit synthetic mutations or use them in real candidate.
- Interrupted process/download: stop only VM test updater, check old pointer, restart Launch.cmd, retry after releasing lock. Failed staging directories can remain; retain logs and clean only confirmed inactive test folders.
- Migration: world_smoke on production bridge proves VACUUM INTO backup, integrity, schema and replay; additionally use disposable legacy campaign, invoke map/view or explicit test fixture migration only as supported, compare actor/inventory/master/campaign log and sibling data, verify backup contains pre-world schema, reopen old game on a restored copy. Actual migration does not imply whole-profile rollback.
- Inspect visual workspace/map at 1280x720 and 1920x1080 with long/empty inventories, visibility/fog/annotation/route fixtures and fallback art; ensure composer and travel remain disabled. Mock provider integration via coordinator suite; no live Gemini unless authorized.

## C. Rollback and eventual deployment
The current updater stages beside old installation; atomic pointer replace is not a database/settings rollback. Startup default seeding and cache rebuild can write shared user:// even before activation. Previous process restart is best effort; no automatic whole-profile backup exists. Back up all user data on each PC while game closed before any authorized release. To recover after candidate has written user data: close all game/bridge processes, preserve failed state separately, verify known-good project folder/version, restore verified old pointer and whole pre-update user directory from backup without overwriting the only backup; launch old version via Launch.cmd and check characters, campaigns, portraits, settings and logs. Prefer VM snapshot for tests. Never restore stale SQLite files into an open process; no cross-PC save synchronization is implemented.
Before publication, clear/replace two vintage files and re-audit, pass native suites and Windows/manual tests, resolve activation blockers, synchronize version files only when authorized, generate final manifest from immutable exact source and verify all raw download hashes. Test actual HTTP/TLS and production installer on representative Windows 10/11 PCs only after explicit authorization, including older hardware, paths with spaces, limited permissions, antivirus, offline interruption, disk space and correct root updater version. Root updater does not auto-update via game channel; older installed copies must be inventoried separately. No production rollout or live channel change in Task 06.
