## Owner clarification — AI request budget
A natural-language action receives one Rules-Check interpretation. If Godot rejects it, display the deterministic reason directly (missing item, resource, eligibility etc.); no narration request, AI reconsideration or automatic retry. Successful ordinary actions receive interpretation and narration; supported direct GUI actions use zero AI requests. Additional AI requests are permitted only where a genuinely required attribute is absent from SQLite, to propose the missing attribute for validated persistence; never fabricate RAW or override a mechanical rejection. This is a standing requirement, not evidence that every runtime path has been verified.

## CURRENT OWNER CORRECTION — interpreter lookup pipeline (supersedes preceding AI budget wording)
AI 1 reads the original player input and returns the list of applicable Godot lookups. It is a lookup selector/interpreter, not a mechanical decision-maker. Godot performs the lookups against SQLite, checks ownership/resources/eligibility and owns deterministic mechanics. Godot assembles the unchanged original player message with retrieved applicable rules, relevant game data and verified mechanical results for AI 2 (DM). If Godot rejects the action (e.g. item not owned), return the Godot reason directly to the player, end the turn and await new input; no DM call or AI reconsideration. The sole additional-AI exception is an item the player possesses whose required item attributes are missing: AI may propose those attributes for Godot validation and persistence, then continue the action through Godot. Missing ownership or failed eligibility is not this exception. Do not invent RAW or override deterministic mechanics. This directive describes required architecture; existing implementation compliance is not yet verified. Do not rebuild unrelated systems to implement it.
